# Phase H 长周期战斗优化思路与实施方法

> 本文沉淀本轮围绕逐霜魔、昭冥日月弘光二段延迟、技能栏顺序、长时间 Boss 战的分析方法。后续测试不同场景时，优先复用这里的方法和脚本，而不是直接套用某一个固定结论。

---

## 1. 背景与目标

前期短周期优化主要解决 45s 内的 T20/T21/T21高血量场景，目标是击杀时间最短或固定 45s 内剩余血量最低。后续讨论转向 5 分钟以上持久战，这类场景有明显不同：

- 日月弘光会多轮循环，不再只是起手爆发。
- 停云凝风 CD 为 135s，长战斗中会重复释放。
- 逐霜技能会根据 CD/充能反复轮转，技能栏顺序影响的是长期相位，而不是单次起手。
- 二段比一段强，但不是压倒性强。以当前数据观察，二段满状态下的苍龙啸·煞相对一段满状态约多 19%，不足以支持长时间憋技能。

因此长周期目标应改为：

```text
在固定战斗时域 T 内最大化总伤害
```

而不是只看单轮爆发或短时间击杀。

## 3. 日月 delay 的数学模型

当前引擎下，日月弘光：

- 一段持续 `delay` 秒，若 `delay >= 30` 则一段按 30s 进入二段。
- 二段持续 15s。
- 二段触发后 35s，日月再次可用。

因此可近似建模为：

```text
C(d) = min(d, 30) + 35
```

其中：

- `d` 是二段延迟。
- `C(d)` 是一轮日月周期。

预计战斗时长为 `T` 时，日月轮数近似：

```text
N(T, d) = floor((T - 1) / C(d)) + 1
```

这说明 delay 不是越大越好，也不是越小越好：

- delay 越大，一段更长，单轮覆盖更完整。
- delay 越小，周期更短，长时间内日月轮数更多。
- `delay = 0` 会立刻进入二段，但完全放弃一段；由于二段只比一段强一部分，通常并不划算。

例如：

```text
delay=0:  周期 35s = 二段15s + 空窗20s，覆盖率约 42.9%
delay=30: 周期 65s = 一段30s + 二段15s + 空窗20s，覆盖率约 69.2%
```

所以即使是 2 分钟战斗，`delay=0` 也未必好。补扫 `0~30s` 后，在当前完整推荐技能栏中：

| 时长 | 最优 delay | delay=0 排名 |
| :--- | :--- | :--- |
| 60s | 4s | 第31 |
| 90s | 16s | 第17 |
| 120s | 11s | 第11 |
| 180s | 30s | 第29 |
| 240s | 30s | 第30 |
| 600s | 23s | 第29 |

---

## 4. 不同战斗时长的 delay 倾向

同一套完整推荐顺序下，扫 `0~30s` 后得到的趋势：

| 预计战斗时长 | 当前模型最优 delay | 解释 |
| :--- | :--- | :--- |
| 60s | 4s | 极短时域，快速进入二段有价值，但不能 0s 放弃一段 |
| 90s | 16s | 起手与第二轮相位共同影响 |
| 120s | 11s | 多一轮日月的收益开始体现 |
| 180s | 30s | 3分钟附近，拖满一段更优 |
| 240s | 30s | 4分钟附近，30s 仍略优 |
| 300s | 28s | 进入中长战斗，周期取整开始影响结果 |
| 480s | 27s | 8分钟附近，较短周期更有优势 |
| 600s | 23s | 10分钟附近，23s 多轮循环收益更好 |
| 900s | 24s | 15分钟附近，23/24/30 接近，需要按具体场景重跑 |

结论：

- 短战斗不能直接套 23s。
- 长战斗也不能无脑 30s。
- 应按预计 Boss 存活时间 `T` 重跑 delay 扫描，至少扫 `0~30s`。

## 5. 一段、二段、无日月占比如何理解

“一段/二段/无日月伤害占比”只对某个固定时长 `T` 成立。换成 180s、300s、480s，占比会变化。

它的用途不是证明某个 delay 永远最优，而是解释某个时域下为什么该 delay 更优：

```text
总伤(d, T) = Σ 命中基础价值 × 命中时刻的日月相位倍率
```

日月相位倍率：

- 命中落在一段窗口，吃一段倍率。
- 命中落在二段窗口，吃二段倍率。
- 命中落在空窗，不吃日月。

关键点：

- 不能只看二段覆盖总时间。
- 要看山雨III、山雨II、苍龙、苍龙煞这些高权重技能落在哪个窗口。
- 二段只比一段强一部分时，为了对齐二段长时间憋技能通常亏。

## 6. 辅助职业释放原则

长周期里辅助不要全部等日月。

### 6.1 常驻类 / 高覆盖类

原则：

```text
CD 好了就放
```

原因：

- 这类技能靠覆盖率获益。
- 为了二段长期等待，会损失总覆盖。

适用：

- 慈航、金蛇等长覆盖 Buff。
- 无量、天舞、炎兵、南巫、背水、攻坚、焦土、阳关等常规 Debuff。

### 6.2 中长 CD 爆发辅助

原则：

```text
只做 3~5s 内的小等待，不做十几秒级等待
```

粗略判断：

```text
如果等待 w 秒带来的二段增益 < 等待造成的覆盖率/施放次数损失，则不等。
```

以二段比一段多约 19% 粗估：

```text
18s CD 技能可等待阈值 ≈ 18 * 19% = 3.4s
12s 回层技能可等待阈值 ≈ 12 * 19% = 2.3s
```

因此持久战中，为了二段等 8s、10s、15s 通常不合理。

### 6.3 停云凝风

当前引擎中停云凝风不会延长日月一段/二段 Buff。它的主要价值是延长当时已存在的其他 Buff。

建议：

- 第一波 `8s` 释放较合理。
- 后续按 135s 周期释放。
- 只有当关键辅助 Buff 或日月二段只差几秒时，才考虑微等。

## 7. 逐霜技能顺序原则

长周期技能顺序不是简单“伤害最高放最前”，而是看：

```text
技能长期价值 = 单次价值 × 施放次数 × Buff相位质量
```

高频高价值技能要优先进入循环：

- 山雨III
- 山雨II
- 苍龙
- 苍龙煞

低频技能不应过度挤占前排：

- 银鳞 CD 150s，600s 约 4 次，总占比低。
- 它可以用于特定短时相位，但不应默认排到非常靠前。

清啸：

- 本身是增益技能，但有施法时间。
- 当前策略有 16s 过期保护，过早放会挤掉高频输出。
- 在完整推荐顺序里放在苍龙煞后面，兼顾覆盖与输出节奏。

## 8. 当前可用推荐顺序

### 8.1 完整 11 技能栏推荐

面向 5 分钟以上且不确定具体时长的通用顺序：

```text
枕戈 -> 山雨III -> 龙战 -> 山雨II -> 苍龙煞 -> 清啸 -> 苍龙 -> 鹰扬煞 -> 鹰扬 -> 银鳞 -> 临渊
```

该顺序在 600s、日月/停云循环模型下表现最好，600s 最优 delay 为 23s。

### 8.2 去掉清啸和银鳞后的 9 技能顺序

如果只考虑：

```text
枕戈、龙战、山雨II、山雨III、苍龙、苍龙煞、鹰扬煞、鹰扬、临渊
```

通用更稳的顺序：

```text
枕戈 -> 山雨III -> 龙战 -> 山雨II -> 苍龙煞 -> 苍龙 -> 鹰扬煞 -> 鹰扬 -> 临渊
```

不同战斗时长对比中，它在 120s、180s、240s、300s、480s 都优于另一个候选；只有 600s 时被以下顺序反超：

```text
枕戈 -> 龙战 -> 山雨II -> 山雨III -> 苍龙 -> 苍龙煞 -> 鹰扬煞 -> 鹰扬 -> 临渊
```

因此：

- 如果明确接近 10 分钟，可考虑后者。
- 如果是 5~8 分钟或时长不确定，优先前者。

## 9. 后续换场景的实施方法

后续测试不同 Boss、不同血量、不同辅助配置时，建议按以下步骤：

1. 估计 Boss 存活时间 `T`。
2. 使用新长周期脚本扫 `0~30s` delay，而不是只扫 `18~30s`。
3. 先用 `seeds` 模式跑完整候选：

```powershell
npx tsx scratch/optimize_long_duration_schedule.ts --mode=seeds --duration=300 --delay=0:30 --top=20
```

4. 如果发现最优集中在某个 delay 段，再用 `local` 模式扩大邻域：

```powershell
npx tsx scratch/optimize_long_duration_schedule.ts --mode=local --max-candidates=120 --duration=300 --delay=20:30 --top=30
```

5. 对新结果做解释时，不只看总伤，还要看：
   - 日月轮数 `N(T,d)`。
   - 一段/二段/无日月覆盖。
   - 山雨III、山雨II、苍龙、苍龙煞落入二段的伤害。
   - 高 CD 辅助是否因为等待损失覆盖率。

## 10. 当前结论的边界

本轮结论依赖当前模拟器规则：

- 技能栏每次从第一格重新扫描。
- 日月二段触发后 35s 开始下一轮 CD。
- 停云凝风不会延长日月一段/二段 Buff。
- 逐霜使用当前 `default_overrides.json` 的属性、四代品质与默认起手延迟。

如果后续修改上述规则，特别是：

- 停云可延长日月。
- 日月 CD 起点改动。
- 清啸过期保护变化。
- 技能栏扫描策略从 `FROM_FIRST_EACH_DECISION` 改为指针继续。

则需要重新跑长周期脚本，不能直接沿用当前 delay 和顺序结论。
