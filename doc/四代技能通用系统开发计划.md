## 一、概念定义

### 1.1 什么是四代技能



* 四代技能是**独立实体**，名称形如「玄烛・xxx」「赤乌・xxx」「幽录・xxx」，每个有萤炬 / 皓月 / 曦日三个品质。

* 玩家在 **profile 中佩戴**四代技能（上限 4 个：3 玄烛 + 1 赤乌，每个独立选品质）；DPS、辅助都可佩戴。

* 佩戴后效果分两类（可并存）：


  * **作用本技能**：四代自身是主动技能（伤害 /debuff/buff），品质决定自身数值。例：赤乌・大业浮屠。

  * **作用其他技能**：四代是被动，佩戴后定向增强一个或多个目标技能。例：玄烛・狱龙破→未名斩。

### 1.2 现有三种旧建模（本期保留不动，后续迁移）



| 方式               | 现有例子                               | 做法                       |
| ---------------- | ---------------------------------- | ------------------------ |
| A. 主动四代写死品质      | 赤乌・大业浮屠・曦日                         | 独立 DAMAGE 条目，数值按曦日写死     |
| B. 被动四代效果挂在目标技能上 | 苍龙啸 / 鹰扬折冲 / 清啸横朔 FourthGenPresets | 四代实体缺失，靠 "给目标技能选品质" 隐式触发 |
| C. 独立四代条目但无品质字段  | 赤乌・三味真火、赤乌・敕戒祸根                    | 数值单一                     |

> 一次性迁移登记在 
>
> `doc/四代系统迁移待办.md`
>
> ，本次不改旧数据，保证零回归。

### 1.3 满级约定



* 四代满级 5 级；神通（玄煞禅）满级 20 级。**数值一律按满级存常量**，不做 level 公式。

* 例：鬼王玄烛・狱龙破 `2%*level` → `2*5 = 10%`。

* 公告未说明品质差异的三品质取相同值；有说明的分开（如云蒸霞蔚 30/60/90）。

## 二、数据结构设计（packages/simulation-engine/src/types.ts）

### 2.1 槽位与品质



```
export type FourthGenSlot = 'XUAN\_ZHU' | 'CHI\_WU';               // 玄烛 / 赤乌（FG = Fourth Generation 第四代）

export type FourthGenQuality = 'YING\_JU' | 'HAO\_YUE' | 'XI\_RI'; // 萤炬 / 皓月 / 曦日
```

### 2.2 技能类型新增 "四代被动"



```
export type SkillActionType =

&#x20; \| 'DAMAGE' | 'BUFF' | 'DEBUFF' | 'UTILITY'

&#x20; \| 'FOURTH\_GEN\_PASSIVE'; // 佩戴型四代被动，不进输出循环
```

### 2.3 四代对 "其他技能" 的定向增益



```
export interface FourthGenGrant {

&#x20; TargetSkillIds: string\[];                 // 被增强的目标技能ID（一个或多个）

&#x20; Override: Partial\<PlayerSkillOverride>;   // 叠加到目标技能（攻%/真气%/CD/施法/充能/段数等，能力越多越好，按需使用）

}
```

### 2.4 Skill 扩展字段（不改原字段语义）



```
export interface Skill {

&#x20; // ...原有字段全部保留

&#x20; FourthGenSlot?: FourthGenSlot;    // 玄烛/赤乌（仅四代实体条目需要）

&#x20; FourthGenGrants?: Partial\<Record\<FourthGenQuality, FourthGenGrant\[]>>; // 作用其他技能；作用本技能仍走 FourthGenPresets

}
```



* **作用本技能**：用原有 `FourthGenPresets[quality]`。

* **作用其他技能**：用新增 `FourthGenGrants[quality]`。

* 同一四代可两者并存。

### 2.5 玩家 "已佩戴四代" 配置（仅战斗模拟路径）



```
export interface EquippedFourthGen {

&#x20; skillId: string;              // 四代实体条目 SkillID

&#x20; quality: FourthGenQuality;    // 品质

}
```



* 加到：`SimulationActorConfig`、`AssemblerDpsActorInput`、辅助 Actor 输入（均为 per-actor，DPS / 辅助各自佩戴）。

* **不加** `AgentCalcInput`（单次计算路径本期不做）。

* 上限 4：玄烛≤3、赤乌≤1。

### 2.6 叠加规则（Actor 构造内）



* 顺序：深拷贝白板 → 融合本技能 FourthGenPresets（现有）→ 应用 skillOverrides（现有）→ **应用 equippedFourthGen**（新增，最后）。

* 对其他技能：SkillBonusAttributes **字段级相加**；顶层字段（CD / 施法 / 充能等）按覆盖；多个四代作用同一技能同一属性时**相加**。

* 目标技能不存在：开发模式 console.warn 并跳过，不中断。

### 2.7 路径边界（明确，避免多做 / 漏做）



| 路径     | 入口                                                                      | 本期是否接四代                           |
| ------ | ----------------------------------------------------------------------- | --------------------------------- |
| 战斗模拟   | SimulationScenario → Actor/combat\_loop（agent\_tool sim\_cli、训练场 arena） | **是**，actor 配置加 equippedFourthGen |
| 单次技能伤害 | AgentCalcInput → normalize → calculateDamage（agent\_tool cli、伤害计算页面）    | **否**，页面无品质选择，推迟（见迁移待办第四节）        |

## 四、引擎改造（simulation-engine，仅战斗模拟路径）

### 4.1 新增辅助模块 fourth\_gen.ts



* `applyFourthGenGrants(skillMap, equipped)`：在 Actor 的技能副本上叠加 Grants；导出槽位校验（玄烛≤3 / 赤乌≤1 / 总数≤4，超限抛错）。

* 独立成模块便于单测；未来单次路径若启用可直接复用。

### 4.2 actor.ts



* 构造入参增加 `equippedFourthGen?`。

* 现有融合逻辑不变；技能实例化后：

1. **作用本技能**：四代实体若有 FourthGenPresets \[quality]，对其自身 applySingleOverride；

2. **作用其他技能**：调用 applyFourthGenGrants，把 FourthGenGrants \[quality] 叠加到 this.Skills \[targetId]；

3. 槽位超限抛错。

* FOURTH\_GEN\_PASSIVE 实例化进 this.Skills（供检索），但不进可释放序列。

### 4.3 输出循环过滤



* 所有选取可释放 / 输出技能处过滤 ActionType==='FOURTH\_GEN\_PASSIVE'，不占 GCD、不进 DPS / 辅助循环。

### 4.4 scenario\_assembler.ts



* DPS 与辅助输入都透传 equippedFourthGen → SimulationActorConfig → Actor。

## 七、实施顺序



1. **类型层**：types.ts 加 FourthGenSlot/FourthGenQuality/EquippedFourthGen/FourthGenGrant；Skill 加字段；ActionType 加 FOURTH\_GEN\_PASSIVE；SimulationActorConfig/Assembler (DPS + 辅助) 加 equippedFourthGen（不动 AgentCalcInput）。

2. **辅助模块**：新建 fourth\_gen.ts，实现 Grants 叠加 + 槽位校验 + 单测。

3. **引擎层**：actor.ts 接入（本技能预设 + 其他技能 Grants）；循环过滤被动；assembler 透传（DPS + 辅助）。

4. **数据层**：skills.json 鬼王三阵营加玄烛・狱龙破实体。

5. **编译**：simulation-engine、agent\_tool、web\_app tsc 通过。

6. **引擎验证**：鬼王 Actor，不佩戴 / 萤炬 / 曦日断言未名斩 = 15/25/25；被动不进循环；槽位超限抛错。

7. **agent\_tool 模拟路径**：scenario 支持 + serializeActor 回显 + 鬼王示例 + 文档。

8. **回归**：逐霜 / 释罗 / 涅羽 / 焚香 / 天音 / 昭冥 / 英招 / 天华 regression，确认不带 equippedFourthGen 结果逐字节不变；单次路径结果也必须不变（本就没改）。

10. **Arena UI（最后）**：DPS + 辅助四代装备分组与组装。

## 九、已确认决策（用户 2026-09-13 确认）



1. SkillID 四代标识用 FG（Fourth Generation 第四代），格式 `{CLASS}_{FACTION}_FG_{拼音缩写}`，如 GW\_XIAN\_FG\_YLP。

2. FourthGenGrant.Override 复用完整 PlayerSkillOverride，能力越多越好，不用字段留空。

3. **作用本技能**走 FourthGenPresets、**作用其他技能**走 FourthGenGrants，可并存（术语统一为本技能 / 其他技能）。

4. 旧方式 A/B/C 本期只新增不迁移；一次性迁移登记在 `doc/四代系统迁移待办.md`。

5. 引擎 + 界面硬校验 玄烛≤3、赤乌≤1、总数≤4。

6. 辅助职业同样需要、全职业都做；先做 agent\_tool（模拟路径），arena 界面后置。

7. **四代只做战斗模拟路径（Actor/sim\_cli/arena）；单次计算路径（AgentCalcInput / 伤害计算页面）本期不做，因其页面无四代品质选择，未来页面支持后再做，已登记迁移待办第四节。**
