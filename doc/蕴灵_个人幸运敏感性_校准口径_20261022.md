# 蕴灵：个人幸运值敏感性（实测校准口径）2026-10-22

> 复现：`node node_modules/tsx/dist/cli.mjs scripts/yunling_luck_calibrated.ts 20000 20261022`
> 固定条件：昭武、装备幸运 0、失败 +1 幸运、pity/converge 关闭；每格 20000 次。
> 个人幸运 0 / 100 / 200 / 500 / 1000 / 2000 对应阶梯表各档，4000 / 10000 用于验证「≥2000 是否等价」。

## 一、阶梯表读数

| 个人幸运值 | 达到档位阈值 | 加成 |
|---|---|---|
| 0 | 未达 25 | +0% |
| 100 | 100 | +5% |
| 200 | 200 | +8% |
| 500 | 200 | +8% |
| 1000 | 1000 | +12% |
| 2000 | 2000 | +15% |
| 4000 | 2000 | +15% |
| 10000 | 2000 | +15% |

**表 281 最高档就是 2000 → +15%**，`luckBonus` 对超过最高阈值的输入返回最后一档加成，所以 **2000 / 4000 / 10000 的加成完全相同**。

## 二、结论（先看这里）

| # | 结论 |
|---|---|
| 1 | **2000 点即封顶，4000 / 10000 与 2000 完全等价**：总手数 386.2 / 386.1 / 386.9，差值在 MC 噪声（±1~2 手）内；+15 单级中位 151 / 152 / 153。2000 以上系数固定 +15% 成立。 |
| 2 | **个人幸运对总手数影响比直觉小**：0 → 2000 只从 411.3 降到 386.2 手，**-6.1%**（-25.1 手）；+15 单级中位 170 → 151（-11.2%），均值 129.2 → 123.9（-4.1%）。 |
| 3 | 原因一：加成是**相对百分比**（p × (1+g)），几何分布期望 ≈ 1/p，+15% 理论上限只到 1/1.15 ≈ **-13%** 手数，不是 -15pp 的绝对量。 |
| 4 | 原因二：**软保底窗口硬截断长尾**（校准口径 +13 100~150、+14 135~203、+15 170~255）。「幸运高 → 早成」的收益被窗口下限兜住一部分，实测只剩理论值的一半左右。 |
| 5 | 边际收益递减：0→200（+8%）拿到 -3.6%；200→1000（+4pp）再 -1.0%；1000→2000（+3pp）再 -1.6%。**堆过 1000 点性价比很低**。 |
| 6 | 校准口径抬高整体难度但没改变幸运的相对收益：幸运 0 时 411.3（下限口径 391.4），幸运 2000 时 386.2（下限 355.5），两种口径下幸运的绝对收益都约 25~36 手。 |
| 7 | 若要让幸运「有感」，得改加成模型（百分点加成或直接抬基础概率），继续调阶梯表无效 —— 阶梯表已封顶 15%。 |

> 附注：+13 一行出现「均值 78.1 < 中位 102」，是**双峰分布**——约一半的局在保底窗口前自然成功，另一半被推进窗口，均值被前半段拉低。
