# Phase H 伤害诊断与接续说明

## 目标

当前重点不是继续调 UI，而是确认默认副本仿真为什么击杀过快。诊断要能回答三件事：

- 每次法宝栏从头扫描时，所有技能分别处于什么状态，为什么最终释放某个技能。
- 每段伤害发生时，角色属性、我方增益、Boss 减益和公式乘区分别是多少。
- 伤害过高主要来自属性、我方增益、Boss 减益、Boss 血量，还是技能释放频率。

## 固化诊断脚本

项目中提供了三个核心诊断/辅助脚本，用于在不同粒度下排查时间线与单段伤害公式。

### 1. 主伤害诊断脚本 (`scripts/diagnose_phase_h.ts`)

- **用法**：`npx tsx scripts/diagnose_phase_h.ts [参数]`
- **核心功能**：
  - **事件流水打印**：指定时间段内（`--timeline-seconds`）所有的释放和起手、Buff生效/失效等行为事件。
  - **单段伤害公式trace审计**：指定时间段内（`--audit-seconds`）每一次主输出的详细属性、增益减益汇总、乘区与 trace。
  - **自定义过滤**：可通过 `--audit-skills` 指定审计特定技能，通过 `--hit-output` 输出 tsv 格式供直接贴入 Excel 横向对比，或 jsonl 格式供系统对接。
  - **消融测试**：通过 `--ablation` 逐步剥离单个/所有辅助职业，查看击杀时间和伤害曲线的变化，回答“为什么击杀过快”。
  - **属性覆盖**：可通过 `--profile` 动态传入用户角色属性 profile JSON。

- **常用命令示例**：
  ```bash
  # 打印 50s 事件流水和 12s 内的单段公式详细 trace
  npx tsx scripts/diagnose_phase_h.ts --timeline-seconds=50 --audit-seconds=12
  
  # 仅查看 12s 事件流水，不打印公式 trace，关闭消融测试
  npx tsx scripts/diagnose_phase_h.ts --timeline-seconds=12 --audit-seconds=12 --ablation=false
  
  # 审计 ZS_MO_SKILL_SY2 单一技能前 8.2s 的 JSONL 命中快照
  npx tsx scripts/diagnose_phase_h.ts --timeline-seconds=0 --audit-seconds=8.2 --ablation=false --hit-output=jsonl --audit-skills=ZS_MO_SKILL_SY2
  
  # 审计 ZS_MO_SKILL_SY2,ZS_MO_SKILL_CLXS 前 12s 的 TSV 扁平格式伤害明细（便于粘贴至 Excel 对齐数值）
  npx tsx scripts/diagnose_phase_h.ts --timeline-seconds=12 --audit-seconds=12 --ablation=false --hit-output=tsv --audit-skills=ZS_MO_SKILL_SY2,ZS_MO_SKILL_CLXS
  
  # 覆盖 DPS 起手延迟、禁用三碗与副本绿点，并打印 8s 流水
  npx tsx scripts/diagnose_phase_h.ts --dps-start-delay-ms=0 --sanwan=false --dungeon-green150=false --timeline-seconds=8 --audit-seconds=5 --ablation=false
  
  # 对 T21 Tier 的副本和 Boss 运行 50s 的完整消融诊断
  npx tsx scripts/diagnose_phase_h.ts --tier=T21 --timeline-seconds=50 --audit-seconds=12
  ```

- **可选开关说明**：
  - `--dps-start-delay-ms=5000`：主输出自动策略开始时间，默认 5000。
  - `--sanwan=false`：关闭开场三碗专注 +20。
  - `--dungeon-green150=false`：关闭开场副本绿点 +150。
  - `--hit-output=both|tsv|jsonl|none`：逐段伤害输出格式。
  - `--audit-skills=ZS_MO_SKILL_SY2`：只输出指定技能的逐段审计（逗号分隔）。
  - `--profile=path/to/profile.json`：传入主输出的角色配置属性 JSON 文件以替代默认的 DPS 属性。

- **输出分区说明**：
  - `INITIAL_EFFECTS`：0s 注入的通用/副本效果。
  - `SKILL_CDS`：魔逐霜默认队列中每个技能認 CD、施法、充能、自然回层、过期时间。
  - `LOADED_ACTOR_SKILLS`：装配后每个 Actor 实际加载了哪些技能。
  - `SUMMARY`：Boss 血量、击杀时间、伤害占比。
  - `TIMELINE_FULL_SCAN_FIRST_Xs`：每次决策时完整扫描 10 个法宝栏技能，列出 `READY`、`cd_until`、`expiry_until`、`no_charge_until` 和最终选择。
  - `BUFF_APPLY_FIRST_Xs`：前 X 秒内所有 Buff/Debuff 的来源、目标、数值和结束时间。
  - `AUDIT_SNAPSHOTS_FIRST_Xs`：前 X 秒首段/末段命中的属性、总增减益、乘区、参与公式的每个效果来源。
  - `DAMAGE_HIT_TSV_FIRST_Xs`：前 X 秒内每一段伤害的扁平 TSV 字段，便于粘贴到表格中横向对比。
  - `CALCULATOR_INPUT_JSONL_FIRST_Xs`：前 X 秒内每一段伤害的完整 JSONL 输入快照，包含 Boss、cap、角色属性、技能段参数、Buff/Debuff totals、公式 trace、入公式效果来源。
  - `ABLATION`：消融测试，逐步去掉部分辅助增益/减益，看击杀时间变化。

---

### 2. 多角色详细时间轴打印脚本 (`scratch/print_timeline.ts`)

- **用法**：`npx tsx scratch/print_timeline.ts`
- **核心功能**：
  - **多角色流水展示**：打印 0 ~ 20 秒内多角色技能释放与 Buff 生效/过期的详细流水，附带中文角色名标签与清晰的控制台排版。
  - **Buff 延时追踪**：包含了对 `BUFF_EXTEND`（Buff 延长）事件的检测和日志，能够明晰展示哪个技能在何时延长了主输出身上的哪些 Buff，新终点是多少，非常适合诊断停云凝风等技能与主输出 Buff 过期点的瞬时联动。

---

### 3. 微观单段伤害输出脚本 (`packages/simulation-engine/src/read_dps_logs.ts`)

- **用法**：`npx tsx packages/simulation-engine/src/read_dps_logs.ts`
- **核心功能**：
  - **超精简极速诊断**：自动装配 6人团队，并只输出**前 15 段命中伤害**的微观细节。
  - **明细包含**：触发绝对毫秒数、命中次数段数、实际造成的伤害数值、理论平均伤害、以及当时生效的全部 Buff 实例 ID 列表，便于极其微观的单段伤害排查。

## 技能栏与充能口径

- 法宝栏自动释放使用 `FROM_FIRST_EACH_DECISION`：每次决策都从第一个技能重新扫描。
- 技能满足两条才释放：一是技能可用，二是配置的过期时间已到。
- 过期时间 `0` 表示不等待过期，技能可用就释放。
- 充能技能只要当前层数大于 0 就可释放；诊断里的 `cdReady` 对充能技能表示下一次自然回层时间，不是有层数时的释放阻塞。
- JSON 里的 `Cooldown` 单位是秒；诊断里的 `ready=21.136s` 是绝对时间点。
- 魔 `山雨欲来II` 和魔 `临渊敛爪` 只给普通 `苍龙啸` 补一层充能，不影响 `苍龙啸·煞`。

## 当前最可疑的核对点

优先级按影响和不确定性排序：

1. 副本绿点 150 是否应被炎兵灸魂翻倍：当前 `150 + 背水300 + 焦土40 = 490`，炎兵灸魂后变 `980`，再按绿点 cap 900 入公式。
2. `YZ_FO_SKILL_BS` 背水：去掉后 T20 从 `44.202s` 变 `77.237s`。需确认绿点 300、易伤 40、持续 27 秒是否符合当前目标场景。
3. 焚香大易伤：绝情殇 60 + 赤乌 50 + 背水 40 + 无量 15 + 无量禅 15，第一段时易伤 raw 已经 180，按 120 cap 入公式。
4. `ZM_FO_SKILL_RYHG` 日月弘光：一段给专注 45、巫咒 7.5，去掉后从 `44.202s` 变 `61.570s`。需确认默认是否应自动释放，以及巫咒是否是独立乘区。
5. `TH_FO_SKILL_QSYY` 秋声雅韵：当前动态专注 42，去掉后只从 `44.202s` 变 `46.755s`，影响比旧基准小，但仍需确认动态公式、默认释放目标和是否应进入当前阶段。
6. 专注公式：当前 `focusMultiplier = 1 + 专注 / 100`，专注 204 即 `3.04x`。需和【诛仙副本战力计算器】逐项对齐。

### 2. 为什么实际效果“差不多”？

从测试结果中我们可以明确地看出，调整技能顺序后，不论在 T20 还是 T21 甚至长时间的高血量战斗中，两套顺序的输出效果确实“非常接近”，其根本原因在于**天人合一（挂机）扫描决策的动作对称性**与**重置冷却机制的对应性**：

1. **技能定位与动作参数完全对称**：
   - 普通苍龙啸（CLX）与苍龙啸·煞（CLXS）在实战中具有完全相同的施法动作时间（基础 3.0s，在当前的迅疾与龙战双重缩短后，均收缩为 0.96s/30-31 帧）。
   - 两者均为最大 3 层充能。
   - 默认顺序中，普通苍龙啸通过 `鹰扬折冲` 瞬间回满充能；煞优先顺序中，苍龙啸·煞通过 `鹰扬折冲·煞` 瞬间回满充能。
2. **天人合一扫描的顺序拦截**：
   - **默认顺序下**（普通苍龙排前）：策略开启后会疯狂连发普通苍龙啸打完 3 层充能。在第 9.0s 施放 `鹰扬折冲` 瞬间补满普通苍龙的 3 层。因为普通苍龙依然放在天人合一的前置格子，扫描时会再度将其拦截并连续打完，一直到 14.62s 普通苍龙充能彻底耗尽，扫描指针才第一次跳过普通苍龙，开始释放后面的苍龙啸·煞。
   - **煞优先顺序下**（苍龙煞排前）：动作逻辑完全相反。起手连续连发 3 次苍龙啸·煞打空充能。在第 9.0s 释放 `鹰扬折冲·煞` 补满煞的 3 层并继续连发打空。一直到 13.66s 煞充能耗尽后，指针才跳过煞，开始释放后面的普通苍龙啸。
3. **输出特性的对称对消**：
   - 默认顺序是“打满普通苍龙 + 鹰扬重置 ➜ 再打煞”；煞优先顺序是“打满煞 + 鹰扬煞重置 ➜ 再打普通苍龙”。
   - 在 33.6 秒甚至更长的战斗内，双方在总动作循环里能够塞进去的普通苍龙与煞的总释放次数完全一样，唯一的区别是哪一个先放、哪一个后放（即输出波峰出现的先后顺序不同）。
   - 随着战斗时长拉长（120 秒），两者的平均 DPS 差距会因为进入多轮冷却收敛而进一步缩减（在 120 秒高血量战斗中，两者的 DPS 差距仅剩 0.27%）。

### 3. 是否有必要将诊断基准换成 T21 级别的第一关 Boss？

**有必要，且非常关键。**

- **避开 T20 阶段的超速击杀溢出**：在 T20 副本中，Boss 赤梭血量仅为 1244 亿，修复施法速度后在 22 秒内就被打死，此时临渊敛爪、银鳞玄冰等长 CD 或低优先级技能根本没机会释放，或者只放了 1 次，无法真实评估循环占比。
- **让技能循环更平滑**：T21 的第一关 Boss 血量为 1968 亿，可以将击杀时间拉长至 33.6s 以上，使后置技能（如临渊敛爪、银鳞玄冰）在战斗中正常释放（临渊占比从 0% 提升至 2.2%~2.8%）。这有助于我们在仿真中观察到更为真实的“技能全循环”表现。
- **防止斩杀期首尾动作偏差导致的误判**：超短战斗（22s）极易因为最后一段伤害落下的微妙帧差导致击杀时间产生抖动（例如 T20 下由于少放了 1 个银鳞玄冰导致煞优先顺序在斩杀阶段慢了 0.29s）。换成 T21 级高血量 Boss 或使用 10000 亿血量诊断，可以彻底平滑这些偏差，获取最可靠的技能组合数据。
