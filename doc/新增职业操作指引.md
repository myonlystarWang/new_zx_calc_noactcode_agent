# 新增职业操作指引

> 结论：**只改 1 个数据文件（`skills.json`）**，代码零改动。图鉴职业栏、搜索、计算器、agent_tool 全部自动生效。
> 改完跑一条命令自检：`node scripts/check_class_data.mjs`

---

## 一、改什么（按顺序）

### 1. 技能数据 —— `web_app/public/game_data/skills.json`

新增职业键，四个阵营数组**都要写**（没数据的写空数组占位，别省略键）：

```json
"XIN_ZHI_YE": {
  "XIAN": [],
  "FO": [],
  "MO": [
    {
      "SkillID": "XYZ_MO_SKILL_A",
      "SkillName": "某技能",
      "RequiredClass": "XIN_ZHI_YE",
      "Faction": "MO",
      "SkillImportanceWeight": 1,
      "SkillFrequency": 0.9,
      "Cooldown": 24,
      "CastTime": 2,
      "IsAOE": false,
      "ActionType": "DAMAGE",
      "SkillBonusAttributes": {
        "SkillAttackPercentBonus": [104, 114, 124, 124, 124, 124],
        "SkillAttackFixedBonus": [400, 410, 420, 420, 420, 420],
        "SkillHealthPercentBonus": 6,
        "SkillManaPercentBonus": 5,
        "SkillCriticalDamagePercentBonus": 15,
        "MultiHitConfig": { "HitCount": 6 }
      },
      "Description": "可选：机制说明段（显示在卡片底部）"
    }
  ],
  "COMMON": []
}
```

### 2. 登记图鉴顺序 —— 同文件 `_meta.compendiumOrder`

```json
"_meta": {
  "compendiumOrder": ["ZHU_SHUANG", "NIE_YU", "...", "GUI_YUN", "XIN_ZHI_YE"],
  "classLabels": { "XIN_ZHI_YE": "新职业" }
}
```

- 数组顺序 = 图鉴职业栏从左到右的顺序，**末尾追加即为最后一位**。
- 忘登记不会消失：会自动兜底排在末尾，但体检脚本会 WARN 提醒。
- `classLabels` 里也补一条名称（26 个职业已有，新职业要加）。

### 3. （可选）职业原设定 —— `classes.json`

只在该职业需要"官方名称/种族/描述"时补。图鉴栏名称取自 `classLabels`，不补也能跑。

## 三、字段速查

### 基础字段

| 字段 | 说明 |
|---|---|
| `SkillID` | 全局唯一，建议 `<职业缩写>_<阵营>_SKILL_<名>` |
| `RequiredClass` / `Faction` | 必须与所在位置一致（体检脚本会校验） |
| `ActionType` | `DAMAGE` 输出 / `BUFF` / `DEBUFF` / `UTILITY` / `FOURTH_GEN_PASSIVE` 四代被动 / `ZAO_HUA_PASSIVE` 造化被动 / `XIN_FA_PASSIVE` 心法被动 |
| `Cooldown` / `CastTime` | 单位秒；输出技能 `Cooldown: 0` 表示无冷却 |
| `SkillImportanceWeight` / `SkillFrequency` | 权重 / 频率，用于卡片头部与计算权重 |
| `IsAOE` | 是否群攻（影响卡片「机制类型」徽章） |
| `Description` | 卡片底部机制说明段；不写则按类型给默认说明 |

### 数值字段（7 个，支持「逐段数组」）

| 字段 | 含义 |
|---|---|
| `SkillAttackPercentBonus` | 附加攻击百分比 |
| `SkillAttackFixedBonus` | 附加固定攻击 |
| `SkillHealthPercentBonus` | 附加气血百分比 |
| `SkillManaPercentBonus` | 附加真气百分比 |
| `SkillDefensePercentBonus` | 附加防御百分比 |
| `SkillCriticalDamagePercentBonus` | 附加暴击伤害 |
| `SkillDamageBonus` | 伤害系数 |

- 标量 = 每段同值；数组 = 每段不同值（第 k 段取 `arr[k-1]`）。
- **数组长度必须等于 `MultiHitConfig.HitCount`**，否则引擎 validator 报错、体检脚本 FAIL。
- 展示口径：卡片与技能详情都是**逐段完整序列**（`104/114/124/124/124/124%（6段）`）；数组字段自动跨整行，不需要手工调样式。

### 被动 / 增益发放

| 类型 | 写法 | 效果 |
|---|---|---|
| 造化被动（门派） | `ActionType: "ZAO_HUA_PASSIVE"` + `ZaoHuaGrants: [{ TargetSkillIds: [...], Override: { SkillBonusAttributes: {...}, CooldownReduction: 4 } }]` | 常驻生效、不占四代槽、无需佩戴 |
| 心法被动 | `ActionType: "XIN_FA_PASSIVE"` + 同上 `ZaoHuaGrants` | 同上 |
| 四代被动（玄烛 / 赤乌） | `ActionType: "FOURTH_GEN_PASSIVE"` + `FourthGenSlot` + `FourthGenGrants: { 莹炬\|皓月\|曦日: [...] }` | 占四代槽，按品质分档 |

- `Override.SkillBonusAttributes` 的数值支持数组 → 对目标技能的逐段数组**逐段相加**。
- `CooldownReduction` 是相对减；`Cooldown` 是绝对值覆盖。
- 减冷却类走四代通道（`FourthGenSlot: "XUAN_ZHU"`），别塞进 `ZaoHuaGrants`。

```bash

# 2) 构建（引擎 + 前端）

```

## 五、本次踩过的坑（避免重复）

1. **逐段数组长度 ≠ HitCount** → 引擎 validator 直接报错；写完先跑体检脚本。
2. **图鉴职业栏曾硬编码**（`SkillsView.tsx` 的 `CLASS_ORDER`）→ 已改为读 `_meta.compendiumOrder`，现在新增职业不需要碰代码。
3. **卡片样式不要在 SkillsView 里写 class** → 一律用 `skillCardStyles.ts` 的常量（卡片只有两档字号：主值 12px、其余 11px）。
4. **同一元素不要叠加两个同属性 Tailwind 类**（如 `text-xs` + `text-[11px]`）→ 谁生效由 CSS 生成顺序决定，不是 className 顺序。
5. **值里的中文与数字自动分流字体**（`components/ui/BonusValue.tsx`）→ 数字永远等宽、中文永远 sans，写数据不用关心。
6. **规格文档内部矛盾先对齐再录**：本次岁寒II 的 Grant 表与说明文案不一致（气血 11 vs 15），核对两个独立来源后确认漏了真气 5。
