# 贴图识别 · 极简校对 · 体系分流（设计 v2）

> 2026-10-21 · 替代同日 v1。v2 的三处口径变更：**① 只显示参与计算的参数；② 统一称「角色属性面板」；③ Workers AI 已确认绑定，问题定位到模型调用层**。

## §0 结论速览

| 问题 | 结论 |
|---|---|
| 为什么贴图结果全错 | 后端在模型调用失败时返回**写死的逐霜模板**（`provider:'offline-preview'`），前端不校验 provider 就渲染。真实面板是昭冥·仙，气血 1,604,910 |
| 为什么"思路"也不对 | 一步跳到「T20 实战爆发秒伤」，跳过「这是谁的号 → 想干什么 → 数据够不够」；且把面板上 22 个与伤害无关的字段全铺出来 |
| 为什么左分屏更崩 | 卡片用视口断点（`sm:` 11 处 / `@container` 0 处），500px 左栏仍按 4 列排，标签被挤成竖排 |
| 线上有没有在调模型 | **文本没有，识图完全没接**。`chat` 返回 `local-fallback`、`vision` 返回 `offline-preview`；`vision.ts` 全文无 `env.AI.run` |
| 那 AI binding 白绑了？ | 不白绑：截图显示 Workers AI binding 名为 `AI` 已就绪。但 `chat.ts:122` 用的 `@cf/meta/llama-3.1-8b-instruct` **调用失败被 catch 静默吞掉**，日志里只有 `console.warn` |
| 你能算到什么 | 昭冥·仙**不能算秒伤**：`skills.json` 里昭冥只有佛阵营 4 个技能，仙/魔是空数组 |
| 卡片该显示什么 | 只显示**下一步功能真正消费的输入项**：角色属性面板 7 项、轩辕策 3 项、天缘 2 项 + 可映射词条 |

## §1 失败归因

### 1.1 造假链路三环

| 环 | 位置 | 行为 | 后果 |
|---|---|---|---|
| ① 后端兜底 | `functions/api/copilot/vision.ts:219-241` | 三家视觉模型全失败 → 返回 `provider:'offline-preview'` + 写死逐霜面板（195000 / 148 / 142.5 / 82 / 3,800,000） | 用户以为识别成功 |
| ② 前端启发式 | `web_app/src/services/CopilotService.ts:3457-3498` | API 失败 → 直连智谱；再失败 → 用正则从**用户文本**抠数字，缺的走默认值 | 文本里的数字被当成面板属性 |
| ③ 线性系数 | `CopilotService.ts:3504-3561` | `clamp(ignore/130, 0.6, 1.6)` 乘总伤；硬编码 T20；异常返回「18.65 亿」 | 与引擎无关的伪数值 |

### 1.2 实测事实

| # | 事实 | 证据 |
|---|---|---|
| F1 | 面板 30 项可见属性，引擎只吃 7 项 | `packages/simulation-engine/src/types.ts:20-33` |
| F2 | 面板**没有「对怪增伤」**，卡片却显示 82% | `HomeAIChatStage.tsx:426-430` |
| F3 | 面板直接给攻击区间 `26918-151478`，代码用 `attack*0.9` 编最小攻 | `HomeAIChatStage.tsx:245` |
| F4 | 识别分流只有 `c_panel` / `xyc`；`item` / `general` 退化为纯文本 | `HomePage.tsx:161-199 / 270-307` |
| F5 | **昭冥只收录佛阵营 4 技能**，仙/魔空数组 | `skills.json.ZHAO_MING = {FO:4, XIAN:0, MO:0}` |
| F6 | 训练场不读 AppContext，技能池硬编码 `'ZHU_SHUANG'` | `SimulationArena.tsx:142 / 476` |
| F7 | 本地无 wrangler / .dev.vars，`vite dev` 下 `/api/copilot/vision` 必 404 | 磁盘直查全 MISSING |
| F8 | AI 卡片 0 处 `@container`、11 处 `sm:` | `HomeAIChatStage.tsx` |

### 1.3 线上实测与 binding 结论（修正 v1 判断）

| 端点 | 实测返回 | 判定 |
|---|---|---|
| `POST /api/copilot/chat` | `provider:"local-fallback"` | 三条通道全未命中 |
| `POST /api/copilot/vision` | `provider:"offline-preview"` + 逐霜模板 | 三家视觉模型全未命中 |
| `GET /` | `200 server: cloudflare` | 部署正常 |

**binding 已绑好**（用户截图：`Workers AI` / Name `AI` / Value `Workers AI Catalog`，与 `KV namespace GUESTBOOK` 并列）。所以 `local-fallback` 的真实原因不是"没绑"，而是：

1. `chat.ts:120` `if (context.env.AI)` 通过 → 进 `env.AI.run('@cf/meta/llama-3.1-8b-instruct')`；
2. 该 model id 若已下线/未开通/超配额 → 抛错；
3. `chat.ts:130-132` `catch { console.warn(...) }` **把错误吞掉**，继续走 fallback，响应里看不出任何原因。

而 **识图侧根本没写 `env.AI.run`**（`vision.ts:11` 只有 `AI?: any` 声明）——binding 绑了也永远不会被用到。

两条设计结论：

- **闸门 G14**：所有模型调用失败必须把 `lastError`（截断 200 字）回传，禁止只有 `console.warn`。
- **闸门 G15**：model id 不写死单个值，改为候选表 + 首次失败自动换下一个，并在 `diag` 里显式列出每个 id 的探测结果。

### 1.4 继承的既定原则

1. 有图跳过 L1 直接走 L3；L1 命中即终局。
2. 回答不跳转既有单页面，全部内嵌卡片。
3. 识图数值必须可单点微调并实时重算。
4. 大模型不做精确心算，本地引擎出数。
5. 不猜数据：缺字段标缺失，禁止默认值。
6. 新增 `cardType` 三处同步。

## §2 贴图分流：先判"这是哪个体系"

用户的图不是只有角色属性面板。**识别第一步是判体系，因为不同体系下一步的功能完全不同。**

### 2.1 本期支持的三类

| 体系 `panelKind` | 画面特征 | 下一步功能 | 卡片名 |
|---|---|---|---|
| `character_panel` 角色属性面板 | 左侧血炼/幸运/善恶，右侧攻击区间、致命伤害/致命一击、御/克、抗性 | 算副本秒伤 / 带入计算器 | **角色属性面板** |
| `xyc` 轩辕策 | 技能说明页：`XX斩《英雄》/《大地》/《天空》/《碧海》`，含职业、技能描述、属性词条 | 同技能四策对比 / 技能带入计算器 | **轩辕策** |
| `tianyuan` 天缘属性 | 上玄·佑万·辰须弥 系列部位（刃/甲/盔）、天命等级、若干词条 | 查该部位词条池 / 词条带入计算器 | **天缘属性** |

> 命名统一：**不再出现「C 面板」**，一律「角色属性面板」。

### 2.1.1 轩辕策不是四象（数据实证，2026-10-21）

| 事实 | 证据 |
|---|---|
| 轩辕策 = **技能流派**，共 237 条 | `all_skills_curated_1~3.json` 中 `group_name` 含「轩辕策」的记录 237 条，`group_kind` 全部为 `sub` |
| 分组按职业 | `group_name` 形如 `鬼王·轩辕策` / `青云·轩辕策` / `天音·轩辕策` … |
| 变体恰好 4 种 | `《英雄》`62 / `《大地》`58 / `《天空》`57 / `《碧海》`56 |
| **与四象无关** | 青龙/白虎/朱雀/玄武 在 237 条轩辕策技能中**零出现** |

四象那套（青龙/白虎/朱雀/玄武 × 普通池/英雄池 × 品阶 1–20 的属性洗练，落在 `xyc_rules.json`）是**另一个体系**，本期不并入轩辕策，单列为 `sixiang_pool`（正式名称待用户确认，见 §10）。

所以轩辕策卡只认三件事：**职业、技能名、策类型（大地/天空/碧海/英雄）**，价值在于「同一个技能四种策放在一起比」。

### 2.2 不建卡的其余类型

| 画面 | 处理 | 话术 |
|---|---|---|
| 装备 / 法宝 / 技能 tooltip | 不 OCR，给文字入口 | "说装备名更快，我直接出图鉴卡" |
| BOSS / 副本界面 | 同上 | "先说打哪个副本" |
| 伤害战报 / 战斗统计 | **明确拒识** | "战报不能反推面板，请上传角色属性面板" |
| 他人面板（聊天/论坛截图） | 按角色属性面板处理，卡头标「他人截图，仅供参照」 | 不自动写入你的账号属性 |
| 与游戏无关 | 拒识 | "这张图里没有可识别的游戏属性" |
| 多窗口混排 | 请求裁剪 | "请只截属性区域，一次一张" |

### 2.3 输入形态

| 形态 | 处理 |
|---|---|
| 纯图 | 判体系 → 校对卡 → 默认动作由体系决定 |
| 图 + 文字 | 文字**只用于选默认动作与副本**，**绝不允许从文字取数值** |
| 多图 | 只处理第 1 张，明说"一次一张" |

## §3 识别契约

### 3.1 类型（`web_app/src/services/vision/types.ts`）

```ts
export type VisionProviderId =
  | 'cf-workers-ai' | 'zhipu-glm-4v-flash' | 'siliconflow-qwen2-vl'
  | 'gemini-1.5-flash' | 'zhipu-direct';        // 白名单；offline-preview 不在内

export type PanelKind = 'character_panel' | 'xyc' | 'tianyuan'
  | 'equip' | 'fabao' | 'skill' | 'boss' | 'combat_log' | 'chat_shot' | 'unknown' | 'mixed';

export type FieldUnit = 'point' | 'percent';    // percent 一律 0-100 刻度
export type FieldStatus = 'ok' | 'low_confidence' | 'unreadable' | 'absent' | 'invalid';

/** 只保留"下一步功能会消费"的字段，其它一律不建模 */
export interface FieldCell {
  key: string;              // 'attackMax' | 'beast' | 'level'
  label: string;            // '最大攻' | '四象' | '天命等级'
  unit: FieldUnit;
  value: number | string | null;
  raw: string | null;       // 面板原文，必须能在 textLines 里找到
  status: FieldStatus;
  confidence: number;
  source: 'vision' | 'user' | 'none';
  engineKey?: keyof CharacterAttributes;
}

export interface ValidationIssue {
  severity: 'block' | 'warn' | 'info';
  code: 'MIN_GT_MAX' | 'REQUIRED_MISSING' | 'FIELD_UNREADABLE' | 'OUT_OF_RANGE'
      | 'RAW_NOT_IN_TRANSCRIPT' | 'PROVIDER_DEGRADED' | 'CLASS_COVERAGE_MISSING'
      | 'KIND_UNCERTAIN';
  fieldKeys: string[];
  message: string;
}

export interface RecognizedPanel {
  panelId: string;
  kind: PanelKind;
  kindConfidence: number;
  kindEvidence: string[];        // 图内可见词
  provider: VisionProviderId | null;
  degraded: boolean;
  degradedReason?: 'no_key' | 'provider_error' | 'route_missing' | 'invalid_json'
                 | 'schema_mismatch' | 'model_not_found';
  lastError?: string;            // 截断 200 字，G14
  imageRef: string | null;
  character?: { classRaw?: string; factionRaw?: string; levelRaw?: string };
  fields: FieldCell[];           // 只含该体系消费的字段（6~7 项）
  extraCount: number;            // 另有 N 项已记录但不参与（仅计数，不建模）
  textLines: { label: string; raw: string }[];
  issues: ValidationIssue[];
}

export interface VisionEnvelope {
  ok: boolean;
  provider: VisionProviderId | null;
  degraded: boolean;
  degradedReason?: RecognizedPanel['degradedReason'];
  lastError?: string;
  panel?: RecognizedPanel;
}
```

> `extraCount` 是"极简"的关键：面板上另外 22 项**不建模、不渲染**，只记成一行"另有 22 项已记录"。既满足"只显示参与计算的参数"，又不丢信息（存档里保留 `textLines`）。

### 3.2 Prompt 五段式（替换 `vision.ts:24-59`）

| 段 | 内容 |
|---|---|
| A 禁令 | "你是截图录入员，只转录不推断。不计算、不补全、不美化。禁 LaTeX、禁 markdown 包裹。" |
| B 判体系 | `panelKind` ∈ 三主类 + 其余枚举；`kindEvidence` 必须引用图内可见词（如「须弥刃」「青龙」「致命一击」）；`kindConfidence` 0-1 |
| C 逐行转录 | `textLines: [{label, raw}]`，按视觉顺序抄一遍，包括看不懂的行 |
| D 取字段 | 只输出该体系需要的那几项（§4 的表），`raw` 必须来自 C 段；没看到就 `absent` |
| E 正反例 | 反例："本面板没有『对怪增伤』行 → 必须 absent，**不得填 78 / 82 / 65 / 49.6**" |

模型输出示例（角色属性面板）：

### 3.3 校验（`parseVisionResponse.ts`）

| 校验 | 规则 | 不通过时 |
|---|---|---|
| V1 | `panelKind` 在枚举内且置信 ≥0.55 | `unknown` + 拒识 |

## §4 只列参与计算的字段

### 4.1 角色属性面板 —— 7 项（与伤害计算器输入一一对应）

| 面板原文 | key | engineKey | 单位 | 说明 |
|---|---|---|---|---|
| 攻击 `26918-151478` | `attackMin` / `attackMax` | `CharacterMinAttack` / `CharacterMaxAttack` | point | 同一 raw 区间，禁止 `*0.9` |
| 防御 `30545` | `defense` | `CharacterDefense` | point | — |
| 气血 `814972/1604910` | `health` | `CharacterHealth` | point | **取上限** |
| 真气 `1145140/2983930` | `mana` | `CharacterMana` | point | **取上限** |
| 致命伤害 `1889.6%` | `critDamage` | `CharacterCriticalHitDamagePercent` | percent | 0-100 刻度 |
| **（面板无此行）** | `monsterDamageBonus` | `CharacterMonsterDamageIncreasePercent` | percent | **必填缺失 → 手填** |
| — | — | `CharacterCriticalHitRatePercent` | — | **不显示**：引擎里是死字段、计算器面板也没有输入口 |

> 致命一击（261%）虽然面板上有，但引擎不参与伤害计算、计算器也没这个输入框 → **不显示**。
> 御/克、抗性、韧性、精通、命中躲闪、减免暴伤、减免暴击、化灵冲灵、无视减免、血炼值、幸运值、勤奋值、善恶值、元神等级 → **全部不显示**，只计入 `extraCount`。

卡片最终只有 7 格，其中最多 1 格是「未识别 · 点此填写」。

### 4.2 轩辕策 —— 3 项（技能流派识别）

| 截图元素 | key | 类型 | 说明 |
|---|---|---|---|
| 职业 | `class` | string（26 职业内） | `group_name` 前缀，决定可选技能集合 |
| 技能名 | `skill` | string | 如「猛火咒III」「聚灵咒III」「失魂斩」 |
| 策类型 | `variant` | enum(`英雄`/`大地`/`天空`/`碧海`) | 来自技能名里的 `《…》` |

> 属性词条（`xyc_rules.json` 那套）不属于轩辕策，见 §2.1.1。若截图上确实带属性行，只在 `textLines` 里留痕，不进卡、不进计算器。
> 「同技能四策对比」所需数据全部来自 `all_skills_curated_*.json`（同 `group_name` + 同基础技能名的 4 条），不需要 OCR 词条。

### 4.3 天缘属性 —— 2 项 + 可映射词条

| 截图元素 | key | 类型 | 说明 |
|---|---|---|---|
| 部位 | `part` | enum（`上玄佑万辰须弥刃/甲/盔`、旧天缘四部位） | 决定词条池 |
| 天命等级 | `level` | number(0–10) | 模拟器 `initialLevel` |
| 能进计算器的词条 | `attr.*` | number | 仅 `攻击` / `对怪物增伤` / `致命伤害` / `致命一击` 四类 |

> 其余词条（克仙/御佛/抗性…）只计入 `extraCount`。

## §5 校对卡 UI

> 效果对照：`doc/识图校对卡_视觉对标预览.html`

### 5.0 视觉语言：对齐现有图鉴卡，不自造

基准 = `compendium/BossDetailCard.tsx` / `compendium/ClassStatusCard.tsx`。

| 元素 | 照抄基准 | 禁止（当前识图卡） |
|---|---|---|
| 卡根 | `rounded-xl p-3.5 sm:p-4 border border-cyan-500/20 bg-[#121824] shadow-md w-full max-w-xl` | 渐变底 |
| 标题 | `w-1.5 h-4 bg-cyan-400 rounded-full` + `text-[15px] font-black tracking-wide truncate` | 无竖条 |
| 胶囊 | `px-1.5 py-0.5 rounded text-[11px] font-bold border`（青=体系 / 琥珀=注意 / 灰=中性） | 无体系 |
| 数值格 | `flex items-center justify-between px-2.5 py-1.5 rounded-lg bg-black/40 border-white/5`；label `text-[11px] text-slate-400 whitespace-nowrap`；值 `font-mono font-bold text-xs` | 大数字块 + 四色染值 |
| 强调 | 仅核心值 `text-amber-300` | 26px 渐变文字 KPI |

**根治标签竖排 = 行式单元格（label 左 / mono 值右，均 `whitespace-nowrap`）**，比改断点彻底。
