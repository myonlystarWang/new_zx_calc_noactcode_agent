# 诛仙3团队副本模拟训练场方案

## Summary

建议做成 **TS Web 训练场 + 共享模拟引擎 + agent/skill CLI 调用入口**，不建议只做 Python 工作流。

核心判断：玩家要调队伍、调属性、调技能顺序、看击杀时间和覆盖率，这本质是交互式时间轴模拟。Python 适合批量分析，但不适合玩家反复拖排轴、比较方案。TS 引擎可以同时服务 Web 页面和现有 `agent_tool`，skill 仍可通过 CLI 调用模拟结果。

首版目标：**单 Boss 长时间战斗模拟**。主输出完整模拟技能循环，队友职业先只作为 buff/debuff 提供者，不计算队友自身输出。

## Key Changes

- 新增共享 `simulation` 核心：
  - 事件驱动时间轴，单位用秒或毫秒统一。
  - 复用现有单次技能伤害公式作为 hit resolver。
  - 模拟技能施法、CD、段数、buff/debuff 生效与过期、boss 血量扣减。
  - 伤害首版使用平均值，仍保留 min/max 区间用于展示。

- 新增战斗配置 schema：
  - `SimulationScenario`：副本、Boss、模拟时长或 Boss 血量、队伍人数、主输出、辅助职业、开始前 buff。
  - `ActorPolicy`：支持三种出招方式：手动时间轴、固定技能循环、天人合一/法宝栏循环。
  - `EffectDefinition`：buff/debuff 目标、效果、持续时间、CD、是否开怪前可预上。
  - `BossMechanic`：Boss 血量、抗性/减爆伤/压缩、阶段血线或阶段时间点。

- Web 训练场首版页面：
  - 队伍配置：选择 6 人/12 人，主输出角色 + 辅助职业。
  - 主输出配置：属性、buff、技能循环模式、技能顺序。
  - 辅助配置：每个辅助职业的 buff/debuff 技能，支持“按 CD 循环”或“固定时间点释放”。
  - Boss 配置：选择副本/Boss，读取 JSON 血量和阶段点，允许临时覆盖血量。
  - 结果展示：击杀时间、总伤、DPS 曲线、Boss 血量曲线、技能伤害占比、buff/debuff 覆盖率、关键技能命中窗口、空转/等 CD 时间。

- 分析能力：
  - 技能顺序对比：方案 A/B 的击杀时间、总伤、爆发峰值、空窗浪费。
  - 队伍职业对比：换辅助职业后，主输出整场收益和覆盖率变化。
  - 属性对比：沿用当前边际贡献思路，但计算对象从“单技能伤害”升级为“整场时间轴总伤/击杀时间”。
  - 输出 JSON 结果，供现有 skill 生成中文结论。

## Implementation Shape

- 不推翻现有系统：
  - 保留当前 `calculateDamage` 单次技能伤害公式。
  - 在其上新增模拟层，不把时间轴逻辑塞进现有静态计算函数。
  - `web_app/public/game_data` 继续作为数据源，扩展技能、buff、boss 机制 JSON。

- 推荐目录形态：
  - `agent_tool/src/simulation/*`：纯 TS 模拟核心。
  - `agent_tool/src/sim_cli.ts`：CLI 入口，给 skill/Python runner 调用。
  - `web_app/src/features/simulator/*`：训练场 UI。
  - `web_app/public/game_data/simulation_*`：技能运行时、职业辅助、Boss 机制数据。

- 首版不要做完整全队 DPS：
  - 主输出：完整出招、完整伤害、完整属性收益。
  - 辅助职业：只提供 buff/debuff 时间轴。
  - 后续如果数据足够，再让每个队友也变成完整输出 actor。

## Test Plan

- 单技能回归：同一角色、同一技能、同一 buff 下，模拟器的一次命中伤害应等于当前计算器结果。
- 循环规则测试：
  - 手动排轴按指定时间释放。
  - 固定循环遇到 CD 技能时跳过。
  - 法宝栏循环只遍历 7-8 个栏位，CD 中跳过。
- 状态测试：
  - buff/debuff 到点生效、过期、刷新。
  - 辅助按 CD 循环和固定时间点释放结果一致可解释。
  - 极速/施法缩短效果只影响生效期间的施法时间。
- 结果测试：
  - Boss 血量归零时停止并输出击杀时间。
  - 同一方案重复运行结果一致。
  - 属性增加后，整场总伤和击杀时间变化可被 JSON 和 UI 同时展示。

## Assumptions

- Boss 血量由你后续补进 JSON；首版支持手动覆盖血量。
- 首版用平均伤害做确定性模拟，同时展示 min/max 区间，不做随机/蒙特卡洛。
- 首版 Boss 机制做到血量、抗性、减爆伤、伤害压缩、阶段血线/时间点；完整无敌、召唤物、复杂转阶段脚本放第二阶段。
- 玩家最关心主输出训练，因此辅助职业首版只作为 buff/debuff 来源。
- Python 仍可保留为报告/批处理脚本，但不要作为核心模拟引擎，避免 Web 和 CLI 公式分裂。
