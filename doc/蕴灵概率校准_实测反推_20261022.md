# 蕴灵概率校准：用实测手数反推参数（2026-10-22）

> 实测口径（用户提供）：+13 基本 80~120 手、+14 120~150 手、+15 150~190 手；偶尔几手上，少。
> 复现：`node node_modules/tsx/dist/cli.mjs scripts/yunling_calibrate.ts 20000 20261022`
> 固定条件：昭武、装备幸运 0、个人幸运 100、`floor` 口径、失败 +1 幸运。每个方案用二分法把基础概率倍率 k 调到目标中位数。

## 一、结论

| # | 结论 |
|---|---|
| 1 | 当前模拟器 +15 中位 **99 手**，实测 **150~190** —— 偏乐观约 **1.7 倍**，用户「概率太高」的反馈成立。 |
| 2 | 只降基础概率（方案 A）能把中位数调到 170，但 P90 会顶到 250 手软保底，与「基本 150~190」不符。 |
| 3 | 必须同时下移软保底窗口：+13 80~130、+14 110~170、+15 140~200，才能既命中中位数、又把 P95 压在 200 附近。 |
| 4 | 推荐 **方案 C**：+13/+14/+15 基础概率压到官方下限的 **43%** / **61%** / **59%**，保底窗口 +13 100~150、+14 135~203、+15 170~255。 |
| 5 | 低手数尾巴保留：+15 仍有 3.8% 的局 ≤10 手，「几手上」的欧皇情况不会被抹掉；中位 166 手、P95 189 手。 |

## 四、落地改动（已写入 `yunlingSim.ts`）

```ts
// 1) 新增口径 calibrated：官方下限 × 实测倍率（+13/+14/+15）
export const CALIBRATED_K: Record<number, number> = {
    13: 0.43,
    14: 0.61,
    15: 0.59
};

// 2) 校准口径的软保底窗口 [S, C]（其余等级仍 250/300）
export const CALIBRATED_CAPS: Record<number, [number, number]> = {
    13: [100, 150],
    14: [135, 203],
    15: [170, 255]
};

// 3) 默认口径切到 calibrated（DEFAULT_CONFIG.baseMode = 'calibrated'）
```

> 模拟器「概率参数 → 基础概率口径」新增「实测校准」档并设为默认；`官方下限 / 区间随机 / 官方上限` 三档保留原样，可随时对照。
> 装备卡的蕴灵锻造（`YunlingForgeCard`）同步切到校准口径。

## 五、待确认

1. 实测数据是在什么个人/装备幸运下得到的？若实测是满幸运（个人 2000 + 装备 1200），则 k 需再放大，因为要先把 +55% 增益除掉。
2. +11/+12 是否也需要校准？当前中位分别是 10 / 33 手，若实测明显更长需一并压。
3. 软保底窗口是否真实存在？若游戏没有保底，方案 A 的纯几何更"诚实"，但 P95 会到 250。
