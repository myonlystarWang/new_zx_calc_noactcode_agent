## 2. 表 325 记录结构（716 字节 / 条）

一条记录里依次排着 **+11 / +13 / +15 三个段**，每段 216 字节：

| 段内偏移 | 内容 |
|---|---|
| `@段+0` | `level`（int32）：11 / 13 / 15 |
| `@段+4` 起 | 属性块，**每块 16 字节**：`[addon_id:int32][max:float][min:float][出现概率:float]` |
| `@段+196` | **五档概率 × 5 个 float（白/绿/紫/橙/红）**，合计 100 |

**已排除的误读**：段内 `@段+260` 之后到 `@段+196` 之间为 0 填充（属性数少的配置如武器 +11 只有 4 条，后面留空），不要当成字段。

> 属性块里的 `min` / `max` 就是该属性的**白档值**与**红档值**（见 §3），中间三档不落库，由插值规则生成（见 §4）。

## 3. 档位方向：为什么 min = 白、max = 红

三条独立证据同时指向同一结论，没有反例：

1. **官方文字**：官网专题「神机属性」明确写「神机属性的颜色根据**属性值高低**，由低到高分别体现为白、绿、紫、金、红，红色是最高品质」。⇒ 最低值 = 白，最高值 = 红。
2. **表里只有 min / max 两个端点**，没有逐档阈值字段。若颜色不由端点决定，配置里就没有任何信息能生成五档，逻辑上不成立。
3. **概率单调递减**（如武器 +11 为 34/33/18/10/5）。若反序解读（第 1 项 = 红），则红档概率 34% 高于白档 5%，与「红色是最高品质」矛盾，且会与官方数值表的档位分布完全对不上。

因此：`档位 1 = min = 白`，`档位 5 = max = 红（极·神机）`，与代码 `TIER_RATIOS = [0, .2, .4, .6, 1]` 一致。

## 4. 五档取值规则（数值，非概率）

第二/三/四档 = `min + (max - min) × 20% / 40% / 60%`。

**已用官网「神机属性全览」三张表逐格核对通过，无例外**。例：

- 昭武·头盔 真气：2700 / 3600 / 4500 / 5400 / 7200
- 修武·头盔 减免暴伤：1.00 / 1.60 / 2.20 / 2.80 / 4.00

> 早前一度怀疑「减免暴伤」第三档例外，放大原图后确认是低分辨率误读，插值规则成立。

## 5. 五档概率（实测值，Σ 均为 100）

**品质不影响概率**，只按部位分三套：

| 组 | 部位 | +11 池 | +13 池 | +15 池 |
|---|---|---|---|---|
| **A** | 武器、衣服 | 34/33/18/10/5 | 38/33/17/8/**4** | 42/33/16/**6/3** |
| **B** | 头盔、靴子 | 34/33/18/10/5 | 38/33/17/8/**4** | 42/33/16/**7/2** |
| **C** | 腰带、袖甲 | **28/24/21/17/10** | **42/33/18/4/3** | **42/33/20/3/2** |

顺序固定为：`白 / 绿 / 紫 / 橙 / 红`。

### 与旧代码的差异

| 蕴灵 | 旧值（无据） | A 组实际 | B 组实际 | C 组实际 |
|---|---|---|---|---|
| +11 | 34/33/18/10/5 | 同旧 | 同旧 | **28/24/21/17/10** |
| +13 | 38/33/17/8/**3** | 38/33/17/8/**4** | 38/33/17/8/**4** | **42/33/18/4/3** |
| +15 | 42/33/16/**7/2** | 42/33/16/**6/3** | 同旧 | **42/33/20/3/2** |

- 旧值其实是「B 组的 +11」+ 自行构造的两组；`+13` 旧值合计仅 **99**（缺 1），正是构造痕迹。
- 影响最大的是 **C 组（腰带 / 袖甲）**：红档实际为 10% / 3% / 2%，旧值是 5% / 3% / 2%——腰带 +11 的红档被**低估一半**。

⇒ `equip_curated.json` 的 `sj` 人工录入内容与当前客户端**逐字段一致**，无需替换。

## 7. 复现方法（含一个必踩的坑）

**坑**：`zx-elements-data-studio/data/elements_tables_v183.json` 里表 325 的 `offset` 是旧值
（`121,207,576`），文件 2026-09-29 更新后已漂移 **14,948 字节**，按旧 offset 读会读到别的表中间。
**不要**手搓顺序扫描器（在 idx 41 附近约 68.9 MB 处会失衡），直接用 studio 的现成读取器。

```js
process.env.ZX_ELEMENTS = 'D:/PGP/games/诛仙/element/data/elements.data';
const m = require('D:/工作/ww/personal_work/zx-elements-data-studio/tools/infer_v183.js');

const b = m.readRec(325, 1);            // rec 1 = 武器_昭武_B档
const wstr = (o, len) => { let s=''; for (let i=0;i<len;i+=2){const c=b.readUInt16LE(o+i); if(!c)break; s+=String.fromCharCode(c);} return s; };

for (const seg of [68, 284, 500]) {      // +11 / +13 / +15
  console.log('level', b.readInt32LE(seg));
  for (let g = 0; g < 13; g++) {
    const o = seg + 4 + g * 16;
    if (o + 16 > seg + 196) break;
    const id = b.readInt32LE(o), max = b.readFloatLE(o+4), min = b.readFloatLE(o+8), prob = b.readFloatLE(o+12);
    if (!id && !max && !min && !prob) continue;
    console.log('  id', id, min, '~', max, (prob*100).toFixed(0) + '%');
  }
  console.log('  五档', [0,1,2,3,4].map(i => (b.readFloatLE(seg + 196 + i*4)*100).toFixed(0)).join('/'));
}
```

  id 20  0.02 ~ 0.08      42%     ← 技能命中
  id 12  0.03 ~ 0.12      8%      ← 攻击百分比 3.0%~12.0%

level 13
  ...
  五档 38/33/17/8/4

> `addon_id` 到属性中文名的映射，不能直接用表 0 的 `name` 字段——表 0 的 `name` 是「附加固定伤害10 / 减免固定伤害2」这类泛化名，与实际语义不符。本站 `equip_curated.json` 里的中文名是人工校正过的，属可信来源。
